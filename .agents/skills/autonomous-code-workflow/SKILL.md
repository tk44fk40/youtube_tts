# 自律的コード実装 ＆ 品質保証ワークフロー (`autonomous-code-workflow`)

指示を受け、以下の 7 段階自律ワークフローを順次実行すること。

## ワークフロー手順

### Step 0: Issue ・ ブランチ ＆ 計画準備
1. **GitHub Issue 作成**: タスクリスト（`- [ ] タスク名`）付き Issue を作成 (`gh issue create`)。
2. **Issue 連動ブランチ**: `issue-<Issue番号>/<機能名>` ブランチを作成・チェックアウト。
3. **計画書追記**: `implementation_plan.md` ヘッダーに関連 Issue, 作業ブランチ名を明記。
4. **計画承認**: 計画書の作成・更新後は一時停止し、ユーザーの計画承認を得る。

### Step 1: インターフェース（シグネチャ・型）の優先提示と合意
内部実装前に骨組み（スタブ）のみを提示し、ユーザーと型合意を得ること（`Any` 排除）：
- 関数シグネチャ（関数名, 引数型, 戻り値型）
- Google スタイル Docstring (サマリー行, Args, Returns, Raises)
- **型合意**: シグネチャ提示後は一時停止し、ユーザーの明示的な合意を得てから Step 2 へ進む（拡大解釈禁止）。

### Step 2: TDD (テスト駆動) 単体テストの先行作成
合意後、実装前に `tests/test_*.py` へ単体テストを作成：
- モジュール分割 ＆ AAA パターン (Arrange-Act-Assert) 徹底。
- `uv run pytest -v <対象テスト>` を実行し、未実装で失敗することをエビデンス表示。

### Step 3: アトミック（小単位）実装
- `AGENTS.md` 準拠。小単位で実装コードを作成。

### Step 4: ローカル自動コマンド検証
ユーザーへ提示前に以下の検証を実行し、エラー 0 件を実証：
1. `uv run ruff check --fix .`
2. `uv run ruff format .`
3. `uv run pyright`
4. `uv run pytest -v` (コミット直前は `uv run pytest -v --cov=.`)

### Step 5: セルフチェック ＆ エビデンスログ提示
コードの作成・修正後に以下の観点でセルフチェックを実施。
問題や矛盾を検出した場合は自律的に再修正。
セルフチェック結果と、段階別テストログを添付。
- **セルフチェック観点**:
  1. 開発ルール・方針への適合性
  2. 要件適合性・設計整合性
  3. テスト妥当性・網羅性 (エッジケース含む)
  4. 副作用・既存機能への影響
  5. 設定・ドキュメント・関連モジュールとの全体の矛盾がないか
- **アトミック開発時**: `uv run pytest -v <対象テスト>` の合否ログ。
- **最終完了前**: `uv run pytest -v --cov=.` の全テスト ＋ カバレッジ表および未カバー箇所の妥当性評価。

### Step 6: PR 作成 ・ スカッシュマージ
1. **PR 作成**: 本文に `Closes #<Issue番号>` を明記 (`gh pr create`)。
2. **計画書更新**: 計画書に PR 番号/URL を追記。
3. **スカッシュマージ**: メインブランチへマージ (`gh pr merge --squash`)。
