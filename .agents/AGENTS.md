# プロジェクトのルール

## 出力は極力完結にする

- 助長な説明は省略してください
- 憶測を交えず事実のみ出力してください

## 図の出力

- 図を出力する場合はアーティファクト出力して参照を促してください

## チャット履歴

- タイトルは日本語で生成してください

## スクリプト及びコマンドの実行

- Python スクリプトやコマンドの実行には uv run を使ってください
- GitHub へのアクセスには gh コマンドを使ってください

## 作業で使用するスキル

- 適切なスキル（`planning`, `issue-management`, `git-workflow`, `testing-coverage`, `code-quality-checklist` 等）を使用して作業を進めてください。

## 除外ルールの追加について

- カバレッジやRuffルールの除外設定は基本的に修正禁止です
- 除外ルールを追加したい場合は**必ず**理由を説明して承認を得てください

## 修正完了の報告

- 修正が終わったら、再度 Ruff チェックを行ってください
- 修正・対応が完了したら以下を報告してください
  - テスト結果
  - カバレッジ
    - 最終的なカバレッジはエントリースクリプトも含めてください
  - 未カバー箇所の説明
    - 未カバー箇所へのリンク
    - 未カバー箇所のコードの概要を簡潔に
    - 未カバーであることの妥当性
      - 未カバー箇所がある場合は、当該箇所が未カバーでも問題ないか妥当性を検討してください（対象コードの妥当性ではありません）
      - 未カバー妥当性検討に基づいて、必要ならテストを追加して、カバレッジを再計測してください
      - 異常系のテストを安易に省略しないでください

## 日本語の使用

- コードコメント、Docstring、ドキュメント、Issue、PR 等は全て日本語で記載してください
